## 一、文件上传：服务器 vs 容器

### 1.1 方案对比

| 维度 | 上传到服务器 | 上传到容器内 |
|------|-------------|-------------|
| **实现复杂度** | 简单 | 中等 |
| **文件持久化** | ✅ 容器重启不丢失 | ❌ 容器删除后丢失（除非挂载） |
| **多容器共享** | ✅ 可以共享模板文件 | ❌ 每个容器独立 |
| **性能** | 需要复制到容器 | 直接在容器内 |
| **安全隔离** | ✅ 服务器统一管理 | ✅ 容器级隔离 |
| **备份恢复** | ✅ 容易备份 | ❌ 需要额外机制 |

### 1.2 推荐方案：**混合模式**

```
服务器存储（主）
    ↓
  挂载到容器（运行时）
```

**架构设计**:
```
/data/students/
├── student_001/
│   ├── workspace/          # 学生工作区
│   │   ├── my_nav/
│   │   │   ├── launch/
│   │   │   │   └── navigation.launch
│   │   │   └── config/
│   │   │       └── costmap.yaml
│   │   └── my_slam/
│   └── submissions/        # 提交的作业
│       └── task_001.zip
└── student_002/
    └── workspace/
```

**容器挂载配置**:

## 二、工作目录方案详解

### 2.1 推荐：Volume 挂载（持久化）

#### 优势
1. ✅ **数据持久化**: 容器删除后文件不丢失
2. ✅ **跨容器访问**: 服务器可以直接读取学生文件（用于评测）
3. ✅ **备份方便**: 直接备份服务器目录
4. ✅ **性能好**: 直接文件系统访问，无需网络传输

#### 实现方案

**Docker Compose 配置**:
```yaml
services:
  student-container:
    image: edubot/gazebo-ros:latest
    volumes:
      # 学生工作区（读写）
      - /data/students/${STUDENT_ID}/workspace:/home/student/workspace:rw
      # ROS 模板（只读）
      - /data/templates/ros_packages:/opt/templates:ro
      # 共享地图资源（只读）
      - /data/maps:/opt/maps:ro
    working_dir: /home/student/workspace
    user: "1000:1000"  # 非 root 用户
```

**Python 代码**:
```python
import os
from pathlib import Path

def create_student_workspace(student_id: int):
    """创建学生工作目录"""
    workspace_path = Path(f"/data/students/{student_id}/workspace")
    workspace_path.mkdir(parents=True, exist_ok=True)
    
    # 初始化目录结构
    (workspace_path / "src").mkdir(exist_ok=True)
    (workspace_path / "launch").mkdir(exist_ok=True)
    (workspace_path / "config").mkdir(exist_ok=True)
    
    # 复制模板文件
    import shutil
    shutil.copytree(
        "/data/templates/beginner_tutorial",
        workspace_path / "src/beginner_tutorial"
    )
    
    return workspace_path
```

---

### 2.2 备选：容器内创建（不推荐）

如果不用挂载，文件只存在容器内：

**问题**:
- ❌ 容器删除后文件丢失
- ❌ 服务器无法直接访问（评测困难）
- ❌ 需要通过 `docker cp` 复制文件（慢）

**唯一适用场景**: 临时测试容器

## 三、文件上传的实现方案

### 3.1 上传流程

```
学生上传文件
    ↓
服务器接收（FastAPI）
    ↓
保存到 /data/students/{student_id}/workspace/
    ↓
容器自动看到文件（因为挂载）
    ↓
学生在终端执行 roslaunch
```

### 3.2 后端 API 设计

```python
from fastapi import UploadFile, File
from pathlib import Path

@router.post("/upload")
async def upload_file(
    file: UploadFile = File(...),
    target_path: str = ".",  # 相对于 workspace 的路径
    current_student_id: int = Depends(get_current_student_id)
):
    """上传文件到学生工作区"""
    
    # 安全检查：防止路径穿越
    if ".." in target_path or target_path.startswith("/"):
        raise HTTPException(400, "非法路径")
    
    # 构造目标路径
    workspace = Path(f"/data/students/{current_student_id}/workspace")
    target_dir = workspace / target_path
    target_dir.mkdir(parents=True, exist_ok=True)
    
    # 保存文件
    file_path = target_dir / file.filename
    with open(file_path, "wb") as f:
        content = await file.read()
        f.write(content)
    
    return ApiResponse(
        code=200,
        message="上传成功",
        data={
            "filename": file.filename,
            "path": str(file_path.relative_to(workspace)),
            "size": len(content)
        }
    )
```

### 3.3 前端上传组件

## 四、代码编辑器方案

### 4.1 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **Monaco Editor** | 功能强大，VS Code 同款 | 体积大（2MB+） | 完整开发环境 |
| **CodeMirror 6** | 轻量（500KB），可扩展 | 配置复杂 | 平衡方案 |
| **Ace Editor** | 成熟稳定，轻量 | 社区不如 Monaco 活跃 | 简单编辑 |
| **终端 vim/nano** | 无需前端开发 | 学习曲线陡峭 | 高级用户 |

### 4.2 推荐方案：Monaco Editor

**理由**:
1. ✅ VS Code 同款，学生熟悉
2. ✅ 语法高亮、自动补全、错误提示
3. ✅ 支持多种语言（Python, C++, XML, YAML）
4. ✅ 社区活跃，文档完善

**集成方式**:
```bash
npm install monaco-editor
npm install @monaco-editor/react  # React 封装
```

```vue
<!-- CodeEditor.vue -->
<template>
  <div class="code-editor">
    <div class="editor-header">
      <span class="filename">{{ currentFile?.name }}</span>
      <div class="actions">
        <el-button @click="saveFile" :loading="saving">保存</el-button>
        <el-button @click="closeFile">关闭</el-button>
      </div>
    </div>
    <div ref="editorContainer" class="editor-container"></div>
  </div>
</template>

<script setup lang="ts">
import * as monaco from 'monaco-editor'
import { ref, onMounted, watch } from 'vue'

const editorContainer = ref<HTMLElement>()
let editor: monaco.editor.IStandaloneCodeEditor

const props = defineProps<{
  file: { name: string; path: string; content: string } | null
}>()

onMounted(() => {
  editor = monaco.editor.create(editorContainer.value!, {
    value: props.file?.content || '',
    language: detectLanguage(props.file?.name),
    theme: 'vs-dark',
    automaticLayout: true
  })
})

function detectLanguage(filename?: string) {
  if (!filename) return 'plaintext'
  if (filename.endsWith('.py')) return 'python'
  if (filename.endsWith('.cpp') || filename.endsWith('.h')) return 'cpp'
  if (filename.endsWith('.launch') || filename.endsWith('.xml')) return 'xml'
  if (filename.endsWith('.yaml') || filename.endsWith('.yml')) return 'yaml'
  return 'plaintext'
}

async function saveFile() {
  const content = editor.getValue()
  await api.saveFile(props.file!.path, content)
  ElMessage.success('保存成功')
}
</script>
```

### 5.3 文件 API

```python
# 读取文件内容
@router.get("/files/read")
async def read_file(
    path: str,
    current_student_id: int = Depends(get_current_student_id)
):
    workspace = Path(f"/data/students/{current_student_id}/workspace")
    file_path = workspace / path
    
    # 安全检查
    if not file_path.is_relative_to(workspace):
        raise HTTPException(403, "无权访问")
    
    content = file_path.read_text(encoding='utf-8')
    return ApiResponse(data={"content": content})

# 保存文件
@router.post("/files/save")
async def save_file(
    path: str,
    content: str,
    current_student_id: int = Depends(get_current_student_id)
):
    workspace = Path(f"/data/students/{current_student_id}/workspace")
    file_path = workspace / path
    
    file_path.write_text(content, encoding='utf-8')
    return ApiResponse(message="保存成功")
```
