# WorkspacePanel 文件树与编辑器工作台重构方案

## Context
当前 `WorkspacePanel` 已具备基础文件树、上传、删除、新建目录、单文件编辑能力，但核心状态仍是单 `currentFile` 模型，且 `FileTree.vue` 同时承担树渲染、右键菜单、拖拽上传、弹窗与调试逻辑，已经出现明显的职责粘连。用户希望补齐：重命名、树内拖拽移动、拖拽上传区分、多选、剪切/复制/粘贴、内联创建，以及接近 SSH/VS Code 的流畅文件预览体验。

本次重构的目标不是继续在现有单组件上叠功能，而是把 Workspace 重构为“薄组件 + 领域状态 + 命令层 + API 适配层”的结构，在尽量复用现有工程模式的前提下，为后续文件管理器能力提供稳定地基。

## 推荐方案
采用 **“组件层瘦身 + composable 局部 store + command 命令层 + 后端原子文件操作 API”** 的方案。

核心产品规则按本次确认执行：
- 预览体验：**VS Code 式** —— 单击预览、双击固定页签、编辑后自动固定
- 拖拽范围第一期：**仅支持把文件/目录移动到目标目录下**，不做同级 before/after 排序

## 架构重构方案

### 1. 组件层拆分
保留 `WorkspacePanel/index.vue` 作为布局容器，但将 `FileTree.vue` 拆成更小职责单元：

- `WorkspacePanel/index.vue`
  - 只负责左右布局、顶部工具栏、与状态层连接
- `FileTreeContainer.vue`
  - 管理树容器事件：选择、右键、内部拖拽、外部拖入、快捷键焦点
- `FileTreeNodeRenderer.vue`
  - 单节点渲染：图标、名称、选中态、内联创建、内联重命名
- `WorkspaceContextMenu.vue`
  - 基于通用 `ContextMenu` 组件生成菜单 schema
- `EditorWorkbench.vue`
  - 管理 preview tab / pinned tab / dirty 标记 / close guard，内部复用 `MonacoEditor`

### 2. composable / 局部 store 分层
将当前 `useWorkspace.ts` 从“单文件 CRUD 管理器”升级为 Workspace 领域 Facade，并拆出子模块：

- `useWorkspaceTreeState.ts`
  - 树节点缓存、展开态、加载态、局部刷新
- `useWorkspaceSelection.ts`
  - 单选、多选、Shift 范围选择、右键与选中联动
- `useWorkspaceClipboard.ts`
  - 剪切/复制/粘贴状态
- `useWorkspacePreview.ts`
  - preview / pinned tabs / file cache / dirty guard
- `useWorkspaceCommands.ts`
  - 统一命令入口，供右键、拖拽、快捷键、工具栏复用
- `useWorkspace.ts`
  - 聚合上述模块，作为 UI 层唯一依赖入口

### 3. 命令层统一动作
引入统一命令模型，避免逻辑散落在组件事件中。

建议命令集合：
- `createFile`
- `createFolder`
- `rename`
- `move`
- `delete`
- `copy`
- `cut`
- `paste`
- `openPreview`
- `openPinned`
- `save`
- `uploadExternal`

每个命令统一包含：
- `canExecute`：菜单禁用态 / 快捷键前置判断
- `execute`：调用 API 与状态更新
- `onSuccess / onError`：局部刷新、回滚、提示

这样右键菜单、快捷键、拖拽、工具栏都只触发 command，而不直接操作 API。

## 数据模型演进

### 1. TreeNode 强类型升级
扩展 `edubot-twin-web/src/api/files/types.ts` 中的 `TreeNode`，至少增加：
- `name`
- `parentPath`
- `isSelected`
- `isExpanded`
- `isLoading`
- `isRenaming`
- `isCreatingTemp`
- `childrenLoaded`
- `mtime?`
- `canDrag?`
- `canDrop?`

并在状态层维护集合：
- `selectedPaths: Set<string>`
- `expandedPaths: Set<string>`
- `loadingPaths: Set<string>`
- `pendingOps: Map<string, 'rename' | 'move' | 'copy' | 'delete' | 'create'>`

### 2. 预览与编辑工作台模型
引入以下状态：
- `previewPath: string | null`
- `activePath: string | null`
- `pinnedTabs: string[]`
- `dirtyMap: Map<string, boolean>`
- `fileCache: Map<string, { content: string; encoding: string; mtime?: number; size: number; lastAccess: number }>`
- `clipboard: { mode: 'copy' | 'cut'; paths: string[]; ts: number } | null`

### 3. 拖拽上下文模型
定义统一拖拽上下文，区分内部拖拽与外部上传：
- `dragSource.type = 'internal-node' | 'external-file'`
- `dragSource.paths?: string[]`
- `dragSource.files?: File[]`
- `dropTarget.path`
- `dropTarget.accepts = 'directory-only'`

第一期规则：
- 仅允许“移动到目录”
- 禁止拖到文件
- 禁止拖到自身或自身子孙目录
- 内部拖拽触发 `move`
- 外部文件拖入触发 `uploadExternal`

## 后端接口改造
需要在 `edubot-twin-server/app/api/v1/endpoints/student/files.py` 补齐原子接口，避免前端以“读写拼接”模拟文件系统操作。

建议新增：
- `POST /files/rename`：`{ fromPath, toName }`
- `POST /files/move`：`{ sources: string[], targetDir: string }`
- `POST /files/copy`：`{ sources: string[], targetDir: string }`
- `POST /files/batch-delete`：`{ paths: string[] }`
- `GET /files/stat`：`?path=...`，返回 `mtime/size/type`

约束：
- 所有路径继续复用现有 `validate_path()` 安全校验
- `move/copy/rename` 必须由后端原子执行
- 目录移动要防止目标目录位于源目录子孙路径下
- 对批量操作返回成功项 / 失败项，方便前端做部分失败提示

## 功能分阶段落地

### Phase 1：拆结构，不改能力
目标：先去除 `FileTree.vue` 职责过载。

实施：
- 拆出 `FileTreeContainer` / `FileTreeNodeRenderer` / `WorkspaceContextMenu` / `EditorWorkbench`
- 将现有 `openFile / upload / delete / mkdir` 行为迁入 `useWorkspaceCommands`
- 用通用 `ContextMenu` 组件替换手写 teleport 右键菜单
- 去掉 `loadChildren(node: any, ...)` 的 `any`，改为显式类型

验收：
- 现有功能等价
- 代码职责清晰
- FileTree 只负责树展示与事件抛出

### Phase 2：多选 + 内联创建 + 内联重命名
目标：为复杂文件操作打基础。

实施：
- 加入 `selectedPaths`
- 支持 Ctrl/Cmd 多选、Shift 范围选择
- 新建文件 / 新建目录改为内联临时节点输入
- 重命名改为内联编辑，而不是弹窗
- 右键菜单根据当前 selection 动态变化

验收：
- 单选/多选状态稳定
- 内联创建失败可回滚
- 重命名仅在编辑态占位，不污染常规树节点渲染

### Phase 3：剪切 / 复制 / 粘贴 / 批量删除
目标：命令层成型。

实施：
- 引入 `useWorkspaceClipboard`
- 接入快捷键：`Ctrl/Cmd+C`、`Ctrl/Cmd+X`、`Ctrl/Cmd+V`、`Delete`
- 支持多选后批量删除、批量复制/剪切/粘贴
- 优先等待后端新增原子 API，再接前端命令

验收：
- 菜单与快捷键共用一套命令逻辑
- 批量操作支持失败汇总提示

### Phase 4：树内拖拽移动 + 拖拽上传区分
目标：完成第一期拖拽能力。

实施：
- 在树容器层统一识别 `internal-node` 与 `external-file`
- 外部文件拖入：走上传命令
- 内部节点拖拽：走移动命令
- 目标目录只允许 directory 节点与根容器
- move 成功后只刷新：源父目录、目标目录、当前受影响选中态

验收：
- 内部拖拽不会触发上传
- 外部拖入不会触发移动
- 无效 drop 位置有明确禁止态反馈

### Phase 5：VS Code 式流畅预览体验
目标：实现“像 SSH / IDE 一样快扫文件”的体验。

实施：
- 单击文件：打开 preview tab（临时预览）
- 双击 / Enter：固定为 pinned tab
- preview 文件一旦编辑，自动转 pinned，避免内容被替换丢失
- 关闭 dirty tab 时提示确认
- 引入 `fileCache` + LRU 缓存，打开同文件优先命中缓存
- 使用 `/files/stat` 做后台静默校验，减少重复读取但避免陈旧内容

验收：
- 大量切文件时请求体感明显减少
- 预览与固定页签语义清晰
- dirty 文件不会因继续浏览而丢失

## 关键交互规则

### 预览与页签规则
- 单击：替换当前 preview tab
- 双击 / Enter：固定为 pinned tab
- 编辑后：自动从 preview 升级为 pinned
- 关闭 dirty 页签：确认后关闭
- 切换到其他文件：若当前只是 preview 且未修改，可直接替换

### 拖拽规则
- 第一阶段只支持“拖到目录中”
- 不支持同级排序
- 不支持拖到文件上
- 多选拖拽默认以当前选中集为单位执行
- 若选中集包含父子路径，执行前做去重，父目录优先

### 多选规则
- 普通点击：单选
- Ctrl/Cmd：增减选中
- Shift：按可见树顺序范围选择
- 右键点击未选中节点时：先切换 selection 再弹菜单
- 右键点击已选中节点时：保留当前 selection

## 验证方案

### 前端交互验证
1. 打开 `WorkspacePanel` / `FileManager` / `CodeEditor`，确认旧功能不回退
2. 验证单击预览、双击固定、编辑后自动固定
3. 验证多选、右键菜单、快捷键是否一致
4. 验证内联创建 / 重命名失败时是否回滚
5. 验证内部拖拽移动与外部拖入上传是否正确区分
6. 验证 dirty guard、关闭确认、保存后缓存同步

### 后端接口验证
1. 对 `rename / move / copy / batch-delete / stat` 做接口级测试
2. 验证路径穿越防护在新增接口中仍然成立
3. 验证目录移动到自身子目录时被拒绝
4. 验证批量操作的部分失败返回结构

### 联调验证
1. 在真实工作区目录下执行：
   - 单文件重命名
   - 多文件复制/粘贴
   - 剪切后粘贴到其他目录
   - 目录拖拽移动
   - 外部拖入上传多个文件
2. 验证树局部刷新是否正确，不出现旧位置残留与重复节点
3. 验证编辑缓存命中、后台校验与保存后的内容一致性
